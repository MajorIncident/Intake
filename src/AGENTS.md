# Runtime module guidelines

## Scope
This file applies to ES modules under `src/`.

Keep feature modules independently initialisable, own only their feature-specific DOM, and communicate mode changes through the existing `intake:mode-changed` event. Presentational features must not extend the persisted intake schema unless their state is genuinely user-authored.

`collaboration.js` owns the `[feature:collaboration]` menu, `[feature:collaboration-presence]` strip/dialog, recovery key, and local-only collaboration profile. It synchronizes only complete `collectAppState()` snapshots through revision-controlled workspace requests; team metadata and presence must remain on their separate API path and must never enter the intake snapshot. Never log workspace tokens, participant identities, presence lists, or snapshot content.


## Classroom coaching modules

`coachableFields.js` owns stable coaching target identity and deterministic field fingerprints. Persistence identity must remain domain-based (`problem.one-line`, `kt.where-location`, etc.); DOM IDs and KT row bindings are rendering hooks only. Do not add ephemeral Possible Cause identifiers to the durable registry without first defining stable lifecycle identity.

`classroomCoaching.js` owns Instructor coaching controls and Student read-only feedback presentation. Coaching is presentation plus a separate Classroom API channel: never add it to `collectAppState()`, `kt-intake-full-v2`, summaries, templates, or collaboration snapshot revisions. Student mode may only read feedback; Instructor controls must remain interactive while the observed Student Intake remains read-only.


## Classroom join sharing

`classroomJoinLink.js` owns the human-code convenience-link contract shared by Instructor and Student entry. Join links may contain **only** the short human class code in a client URL fragment (`#join=...`); never place Instructor, Student-session, assignment, workspace, collaboration, or other bearer capabilities in a join URL. Share-link construction must discard the current page query string so a pre-existing `?workspace=` collaboration capability cannot be forwarded accidentally. `experienceRoleController.js` may use a valid join intent to select Student experience, but existing Standalone `?workspace=` links take precedence. `classroomStudent.js` may consume/prefill a join fragment only through the normal admission UI/API and must not silently replace an existing saved Student class session.

## Protected Classroom resources

`classroomExerciseInstructor.js` owns the Instructor staged-exercise console client. It receives the Instructor capability only through the class lifecycle, keeps that credential and exercise payload in memory, and reads/writes `/api/classes/exercise`; draft selection/create may POST only an explicitly discovered staged `caseStudyId`. Start/Pause/Resume, current-stage `release-content`, Begin Debrief, debrief-only `set-editing`, Advance, and Complete mutations must send the currently observed `exerciseRevision`; a 409 must reload authoritative server state rather than replay stale intent. Advance may only follow the authored protected stage order and only from active debrief with a next stage; Complete may only occur from active final-stage debrief. Advancing returns the next stage to work with Student editing enabled. Completion is terminal presentation, must hide further edit/lifecycle actions, and must never imply that completion releases future, Instructor-only, exemplar, or full protected Case Study material. Release UI may render only the current stage's explicit `optionalReleaseIds`, never future-stage Student content. Team readiness/progress must come from the Instructor-authorized `workspaceState` payload and reuse the existing Instructor `selectWorkspace()` observer/coaching path. Debrief checkpoint UI may expose capture status, workspace identity, and captured workspace revision. Snapshot bytes may be fetched only after an explicit Instructor **Inspect checkpoint** action; `classroomExerciseInstructor.js` must pass that snapshot transiently to the existing Instructor observer renderer and must never retain it in controller public state, persistence, exports, summaries, or resume state. Checkpoint view must be read-only, pause live observer/coaching projection for that workspace, clearly identify the captured revision, and provide an explicit return to current live observation. It must never create an editable checkpoint copy or treat the snapshot as collaboration state. `studentEditingEnabled` is authoritative presentation only; the server-side 423 collaboration write guard remains the actual freeze boundary while an active staged policy applies. Current-stage Instructor facilitation may render only in Instructor experience. Exercise state, staged definitions, releases, readiness, checkpoints, and capabilities must never enter Intake persistence, summaries, exports, URLs, or public manifests.

`classroomExerciseStudent.js` owns the Student staged-exercise case-reference client. It may receive only the stable live Student class-session capability, keep it in memory only, and GET `/api/classes/exercise/student`; it must never use the assignment/workspace capability as staged exercise authority and must never fetch the complete protected Case Study payload. Render only the sanitized case summary, current Student-visible stage/objective, authoritative exercise phase/edit-policy state, and cumulative released Student-safe content actually returned by the Student endpoint. Unknown response fields, future-stage metadata, Instructor-only material, exemplar/model content, and bearer capabilities must not enter DOM/public controller state. The reference must survive workspace reassignment because class-session authority is stable, but must clear immediately on class-session termination or role exit. Exercise content/state must never enter Intake persistence, localStorage/sessionStorage, summaries, exports, URLs, or public manifests. Mobile collapse/expand state is local presentation only; narrow layouts must not let the case reference or team/notes workspace obscure each other.

`classroomStudent.js` distinguishes two lifecycles: workspace-level `onClassConnected/onClassDisconnected` hooks rotate with assignment authority, while live-session `onSessionConnected/onSessionDisconnected` hooks represent the stable Student class-session capability. Do not conflate those credentials; reassignment must rotate workspace authority without reconnecting the staged exercise session.

`classroomInstructor.js` owns the connected Instructor class rail. Its collapse/expand state is local presentation state, not Intake/session authority. Narrow screens default to the compact collapsed class header, but the class controls must remain explicitly discoverable through an accessible Open/Collapse control; do not hide the Instructor workspace surface on mobile without an equivalent launcher.

`classroomCaseStudies.js` owns the authorized in-memory protected Case Study catalog/payload client. It receives active capabilities only through Student/Instructor lifecycle callbacks, keeps no localStorage/sessionStorage record, and clears catalog/context when the class role disconnects. Its public state must never expose a bearer capability.

`templatesDrawer.js` may combine public Standard Template metadata with the current authorized in-memory Case Study catalog, but must fetch a protected payload only on demand and project it through `projectTemplateState()`. Standalone must work with no protected provider or classroom backend.

Browser modules must never import `api/protected-case-studies.manifest.js` or refer to protected Case Study IDs/names. `npm run verify:protected-cases` enforces this boundary. The rotating Case Study password remains instructional UX, not authentication.
